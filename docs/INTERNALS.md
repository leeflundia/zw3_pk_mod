## 1. 委任机制（`deleg_*`）

### 1.1 v210 三 bug 修复（"delegpersist" 版本的核心工作）

- **bug1/bug3（`g_deleg_cfg` 数组 + `deleg_set_tier` + `deleg_toggle`）**：⛔不再"凡 0 档一律拉满"。
  用户主动把某项设成"关闭"（档=0）后，取消再开启委任曾被误重置为满（士兵 40000 等）。
  规则：**只有【从未配置过】的新城才填默认满档**；已配置过的城（含把某项关成 0 的）原样保留。
  "配置过"的判据 = `g_deleg_cfg[c]`（toggle 重开或改档时置 1）。
- **bug2（`detect_mode` 详情页启发式）**：命令菜单页（ctrl 在 MENU_CTRL 窗口）⛔不算详情页。
  根因（与首都无关，10-06 18:12 用户纠正）：detect_mode 判详情页的启发式是 "pg!=0 且 IDX==CITY_MIRROR"——
  命令菜单页上游戏把光标行号写进 IDX，光标行号恰好等于本城镜像号时撞车 ⇒ 误判 MODE_CITY ⇒ 修改器盖在命令菜单上。
  襄平 c2 mirror=1，鼠标进菜单光标默认停第 1 行 ⇒ 必撞（每次弹修改器）；其他城 cursor 落到第 mir 行才撞 ⇒ "有时"出现。
  判据与 `detect_scene` 同源（MENU_CTRL_LO/HI = 菜单页控件指针窗口；全日志 scene3 样本 100% 命中该窗口、scene4 详情页 73 例仅 2 例切换瞬态）。
- **"读档后目标被拉满"的另一半根因（v210①联动）**：此前档位只在 Ctrl+E 退出面板才存盘——
  游戏异常关闭/强杀 ⇒ `settings.dat` 停在旧值。修复：**改档即刻落盘 + 标记已配置**。

### 1.2 档位体系与数值口径

- **目标 5 档制**（`deleg_tier_of` / `deleg_set_tier`）：0 / ¼ / ½ / ¾ / 满（cap）。档位换算**就近取整**。
- **静态预估（`deleg_pct_cache` / v207③）**：无实测值时用静态预估（来源 = v206 取证实测均值：治~105 墙~410 粮~410 兵~165），首执后 EMA 实测覆盖。⛔不再恒问号。
- **预算日志（`deleg_budget_log` / v208）**：分项 = 实测 EMA（0=未实测，按预估计），对照常量表可核预估准不准。`deleg_will` 已把关卡禁用四项滤掉，预算自然只含墙/粮（或空=0）。
- **绝对值入日志（v209③）**：farm/comm 绝对值入日志（此前只记增量，无法核对跨季累积）。

### 1.3 直写显示层（农业/商业"手动差分铁证"）

`deleg_grow_disp`：**农/商走"显示层直写"**——手动农业 = `pool[cityID]+amt` & `unrest[cityID]-amt`，
而 `pool[c-1]` 与农业显示 `farmdisp[c] = CITY_ARR[0]+c*4` 同址（`0x5DDAA8+c*4 == 0x5DDAAC+(c-1)*4`）。
⛔ `RVA_DEV_FARM` 写的是隐藏 `farmdev`（0x5E6994），不驱动面板——委任农业"没涨"即此因。
商业 adder（`0x5F7FA8+ci*4`）== `commdisp[c]` 本就可见，继续用 adder。

- **步进口径（v209①，用户裁定路线 A）**：逐字复刻游戏手动农业开发命令（exe 0x43d2ef / 0x43d29f 两分支同构）：
  `inc = 能力×(档位+2)÷2×不安÷100`。不安高=开荒快、不安耗尽=停涨（与"实际派太守执行"同感）。
  ⛔ 旧 `pol*2+10` = 常数假步长（与档位无关；用户点破"是你自己想的"）。
  商业同构，档位系数放大（原生手动商业命令未反到，标注近似）。

### 1.4 结算与绕闸（`deleg_round_end`）

- **目标未达 ⇒ 临时绕 AI 结算族（0x44d*）的原生闸**（手动族无此限制，语义对齐手动）：
  治=pool0 假闸 / 墙粮=cap 数组×0.8 跳办+终钳 / 兵=势力供养闸+城兵营闸。**办完还原**。
- **第五闸 = DEV 自衰减除数（v207①，反汇编铁证 0x44D5E1 / 0x44D774）**：
  步进 ∝ 常数÷DEV 整除，DEV 过阈商=0 ⇒ done 置位、照扣钱、零产出
  （= c10 粮 99→99 扣 588 / c12 墙 122→122 扣 582 的"白扣钱"真身）。
  检出"置位未动" ⇒ 本窗内（wa 仍抬着，adder 钳制上限=lim）直调原生 dev-adder 补步进，扣掉的钱变真实支出不退。
- **auto 路步进保底 ≥1（v207②）**：南皮 g=8 时 g/10=0 截断 = 墙粮永不涨根因；
  adder 会把超 cap 现值钳回（南皮墙 80>cap 会倒退），临时抬 cap 包裹后还原。
- **重烤规则（`deleg_round_end` 内）**：仅当"表顶本身≤现值"（陈档位死锁，任何档都追不上）才重烤满档；
  用户自选低档且真已达标的（cur<tgt 假 ⇒ 已达标停办 = 正确语义）⛔不动。
- **闸门原因短标签（`deleg_block_reason`）**：目标未达但游戏自己不办时给出短标签（⛔非 MOD 拦截）。
  绕闸状态：治安闸已绕（目标未达必办）/ 城墙 cap 闸已绕 / 兵粮 cap 闸已绕；
  **兵 = handler 内立即数 30000，无法绕**。

### 1.5 设置持久化格式（`settings_*`）

- 路径：存档文件夹内 `zyconf\settings.dat`（读档恢复委任/战死/作弊开关，免重设）。
- **格式版本**：
  - 当前 magic = `ZYSET_MAGIC 0x3253595A`，**新格式含 `cfg` 字段**（`g_deleg_cfg` 落盘）。
  - **旧版（v201~v209）**结构无 cfg 字段，magic = `0x3153595A`；读到它 ⇒ 按"委任已开 或 任一目标非零"推断 cfg
    （老文件里 toggle 开过的城目标都被填过 = 配置过）。开着的城视为配置过。

## 2. 关卡系统（`city_is_gate` 及相关）

- **关卡判定（v208，zydiag 三时刻 dump × 全 148 城标定，两独立表交叉吻合）**：
  `规模上限表 == 50 ∧ 商业上限 == 0` ⇒ 壶关/汜水关/虎牢关/函谷关/潼关/武关/子午谷/散关/斜谷关/狄道/阳平关/雒/绵竹/梓潼/剑阁 **15 城**。关卡无农/商/治安数据、不可征兵。
- **关卡四项禁用**（农/商/治安/兵）：本无数据、兵不可征；**墙/粮照常**（关卡通用）。
- **修改器拒改（`apply_field`）**：关卡无农/商/治安数据 ⇒ 拒绝改（士兵数据存在但不可征兵，改数放行）。
- **委任中**：关卡禁用四项（农商治安兵）不参与重烤，档位保持 0=未选；农/商/治安/兵四项强制未选（档位=0）。
- **界面（`paint` / `nav_deleg`）**：禁用项画"不可用"态（色同整项关闭+右侧短横）；四项不可选档，其余两项（墙/粮）照常。

## 3. 上限与闸门体系（caps）

- **per-city panel display caps（`CAP_TRP_ARR` 等）**：活内存四城交叉验证（邺/阳平/临湘/蓟，全自有城上限≥显示值零违例）。
- **城规模上限表（`DCAP_TRP` / `CITY_SIZECAP`）**：`addr + c*4`，1 基：关卡=50，普通城 86~200（zydiag 全 148 城标定）。引擎层开发度与闸门数组用 cityID=c-1 基。
- **display-block caps 索引口径**：按**名称索引 c（1 基）**，⛔不是 cityID。铁证：真定 c=17 → DCAPfarm[17]=5000（面板），DCAPfarm[16]=2000（中山）。
- **表上限余量（v207）**：表上限≤当前显示值（历史超档如南皮墙 80>表 60）⇒ 给 `cur+40` 余量。
  目的：① 满档目标必须高于现值，否则"永不办"假达标（用户设了档也不涨）；
  ② 原生 adder 的 cap 钳回（80→60=城墙倒退）由两路临时抬 cap 包裹禁止，本函数只负责让档位有推进空间。

## 6. 垫片设计说明

### 6.1 d3d11 垫片（`d3d11_proxy.c`，原文件头注释全文）

> d3d11.dll 代理 **v6-adaptive**（内置面板的自动加载器）
>
> 作用：dgVoodoo2 运行时 LoadLibrary("d3d11.dll")（无路径）⇒ 命中 exe 目录里本文件。
> ① 把 d3d11.dll 的 51 个导出原样转发给"对应环境的真身"（游戏照常运行）
> ② 顺带按优先级加载面板模块（候选名依次尝试，取第一个存在的）
>
> **v6-adaptive**（2026-10-09）：真身选择从"静态先查同目录"升级为"环境感知"——
> · Wine（安卓 Winlator / 盖世容器）⇒ 优先同目录 d3d11_real.dll（DXVK 真身）；失败回退 System32\d3d11.dll
> · 真 Windows ⇒ 优先 System32\d3d11.dll，⛔无视同目录 d3d11_real.dll（防玩家机上误拷/预放的 DXVK 被误接管）；系统缺失才回退同目录
> 判据（双保险）：① ntdll 导出 `wine_get_version`（仅存在性检测不调用）② `HKCU\Software\Wine` 注册表键存在
> ⇒ 发布包可把 d3d11_real.dll + dxgi.dll 一并预放：PC 端零影响、安卓端零操作。
>
> **v6+pin**（2026-10-09 实测补丁）：实测"预放 dxgi.dll 会被系统组件按应用目录优先命中"——
> 产生 *_dxgi.log（DXVK 日志）且游戏在渲染初始化后退出。修复 = 非 Wine 分支在真身加载前"钉钉子"：
> 抢先 LoadLibrary 系统 dxgi.dll 占住模块名（Windows 加载器按 basename 先到先得），
> 此后任何无路径 LoadLibrary("dxgi.dll") 都复用系统版，包内 DXVK dxgi 永不生效。
> 判读日志行：`dxgi-pin=ok/fail`（fail 也不致崩——只是退回"未钉"行为）。
>
> 版本谱系：v2(多候选面板) → v4(候选扩容14) → v5u-unified(静态双档回退) → v6-adaptive(本版)
> 面板模块候选名策略（`CAND[]`）：数字越大优先级越高，换新版放更高编号文件即可（运行中也能放）。

**实现细节点**（原行内注释）：
- `g_envDesc/g_realDesc/g_pinDesc`：真身选择结果——DllMain 在 loader lock 内**只做纯指针赋值**，日志留待 boot 线程写。
- `env_is_wine`：双保险判据（见上）。
- 环境感知选择段：⚠本段在 loader lock 内同步执行——只做 LoadLibrary + 纯指针赋值。
- Wine 分支：DXVK 真身优先（同目录），失败回退系统。真 Windows 分支：系统 d3d11 优先，⛔不碰同目录 d3d11_real.dll。

### 6.2 dxgi 垫片（`dxgi_proxy.c`，原文件头注释全文）

> dxgi.dll 垫片（dxgi proxy）**v1** —— "全放"整合包的最后一环。
>
> 作用：让"包内预放的 dxgi.dll"成为"安全转发器"——
> dgVoodoo / 系统 d3d11 / DXVK d3d11 等组件加载游戏目录的 dxgi.dll 时，拿到的是本垫片，按环境转发：
> · 真 Windows → System32\dxgi.dll（切断"微软组件×DXVK 混搭"事故链）
> · Wine（安卓） → 同目录 dxgi_real.dll（DXVK）
> 判据同 d3d11 垫片 v6：`wine_get_version`（存在性）+ `HKCU\Software\Wine` 双保险。
>
> 背景（2026-10-09 PC 三组实验定案）：dxgi.dll 是"真名字"——DXVK 版裸放游戏根时，
> 系统 d3d11 的静态导入（dxgi.dll→`CreateDXGIFactory2`）会按应用目录优先命中它 → 混搭 → 游戏退出；
> "抢先占名（钉钉子）"修复亦被加载器机制绕过（实测判负）。
> 本垫片把"游戏目录的 dxgi.dll"变成转发层后，两端加载链各自闭合：
> PC：系统 d3d11 → 垫片(CreateDXGIFactory2→) → System32 dxgi ✓
> 安卓：DXVK d3d11 → 垫片(CreateDXGIFactory1→) → dxgi_real.dll(DXVK) ✓
> 且无论谁、何时、以何种路径加载"dxgi.dll"，得到的都是本安全转发器。
>
> 导出：20 个 = 系统 SysWOW64 dxgi 全导出（已覆盖 DXVK x32 dxgi 的全部 5 个）。
> 日志：`dxgi_proxy.log`（与本文件同目录；⛔与 DXVK 的 *_dxgi.log 区分）。

**实现细节点**：Wine/安卓分支同上；**真 Windows 分支：系统 dxgi 优先（完整路径，⛔绝不用无路径名防自命中）**，仅系统缺失才回退同目录。

## 7. 注入器（`injector.c`）

- **为什么必须用 32 位程序**：`CreateRemoteThread` 需要目标进程里的 `LoadLibraryW` 地址，64 位进程取的地址在 32 位进程里无效 ⇒ 注入器必须与目标同为 32 位。
- 用法：`inject.exe <进程名子串> <dll绝对路径>`（如 `inject.exe CHENUEN "C:\...\zy_overlay14.dll"`）。
- 编译：`gcc -m32 -O0 -municode -o inject.exe injector.c`（build.sh 固化）。
- `find_pid` 按进程名子串匹配；远端模块是否真的加载成功 = 看 `exitCode = HMODULE`（0 表示失败）。
